# Admin-created bookings are confirmed without booker verification

Bilag 1 ("The specific booker") verifies the booker's work email with a six-digit code on every booking. That rule holds for every booking a company makes itself. When admin enters a booking on a company's behalf — the only way an external company gets a booking in v1.0 (ADR-0008), and a fallback for members who book by phone or mail — the booking is inserted as `confirmed` at once: no hold, no code. Admin is the trusted actor and cannot read a code sent to someone else's inbox; a hold would only block the room for ten minutes. The booker's name, work email and mobile number are still required, so confirmations and reminders reach a person and admin knows who is responsible (ADR-0004). Availability is still checked by the same no-overlap constraint and house-event trigger as every other insert. Decided 2026-09-14 in #14.
